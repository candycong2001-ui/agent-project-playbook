# {{PROJECT_NAME}} 项目协作约定

## 真值顺序

- 用户本轮指令、当前仓库文件、测试、配置和命令输出高于历史记忆。
- 以当前 Git 根目录或用户明确指定的项目目录为边界。
- 不继承其他项目的事实、状态、凭据、失败经验或实现约定。

## 协作模式

- 探索模式：接受不完整想法；默认讨论、调研和只读检查。
- 启动模式：明确用户、问题、边界、成功标准、命令入口和第一条最小闭环。
- 实施模式：先判断项目阶段和本轮交付物，再形成问题单、垂直切片、验证和交付。

## Design Thinking 映射

- Empathize 共情 → 探索：理解用户、场景、感受和真实阻力。
- Define 定义 → 探索：形成问题陈述、成功标准和边界。
- Ideate 构思 → 探索到启动：比较方向并选择需要验证的路线。
- Prototype 原型 → 启动到实施：选择最小可验证交付物和第一条垂直切片。
- Test 测试 → 实施：用验收证据验证，并在需要时退回前一模式。

三种模式可以循环，不是单向瀑布流程。

## 自动两级任务路由

- 第一级先判断项目生命周期阶段和本轮最需要的交付物；新项目不得默认直接编码。
- 协作模式描述“这一轮怎样合作”，项目阶段描述“产品走到哪里”，不得混为同一字段。
- 项目阶段包括问题发现、启动准备、MVP、功能扩展、稳定运行和维护优化。
- 本轮交付物可以是问题定义、MVP 范围、蓝图、用户故事、架构、原型、演示、代码切片、测试证据、文档、部署或回滚方案。
- 第二级形成问题单：用户证据、推断问题、本轮交付物、切片类型、验收、风险、最小切片和明确非目标。
- Bug、功能、UI、体验、重构、性能、数据、测试、文档和部署属于切片级分类，用户无需自己分类。
- 顺带发现的问题进入停车区，不扩大当前任务。

## 垂直切片纪律

- 每轮只完成一个可以独立验收的闭环。
- 需要时覆盖 UI、后端和数据；相关测试、验证和文档属于完成条件。
- 不把无关重构、视觉美化、性能优化、部署或历史兼容塞进同一切片。
- 重构先保护行为，性能优化先测量，UI/体验修改必须有可观察证据。

## 多 Agent 协作

### 主 Agent 托管

- 用户只与主 Agent 沟通；子 Agent 不接管对话，也不独立宣布完成。
- 主 Agent 负责阶段判断、交付物、问题单、角色分发、冲突处理、最终集成、验证和交付。
- 子 Agent 只接收边界明确的执行任务，并返回产物、证据和剩余风险。

### 模型路由

- Frontier 用于主编排、架构、冲突裁决、高风险复核和失败重规划。
- Balanced 用于常规开发、代码调查、测试分析和文档研究；Fast 用于搜索、分类、抽取、格式转换和大批量只读扫描。
- 当前 Codex 映射为 Sol / Frontier、Terra / Balanced、Luna / Fast。
- 创建子 Agent 时必须显式选择 Terra 或 Luna；默认不创建 Sol 子 Agent，升级后的判断由主 Sol 接管。
- 平台无法选择子 Agent 模型时，退化为主 Agent 顺序执行，不假装完成了模型路由。

### 委派边界

- 只有存在两个以上真正独立的任务时，才自适应并行多个 Agent。
- 小型线性工作、共享状态写入和高风险外部操作不为并行而拆分。
- 主 Agent 必须用当前文件、测试或真实输出复核子 Agent 的关键结论。
- 部署、删除、真实外部写入、凭据操作和最终 Git 交付需要主 Agent 复核与相应授权。

## 项目节奏

开始重要实施或诊断时：

1. 阅读 `docs/CURRENT_HANDOFF.md`。
2. 阅读 `docs/BLUEPRINT.md` 和 `docs/ARCHITECTURE.md` 的相关部分。
3. 用当前仓库证据核对文档。

得到授权的实施过程中：

- 在 `CURRENT_HANDOFF.md` 保留一个当前模式、项目阶段、交付物、问题单和垂直切片。
- 只有产品意图、用户、范围、约束或验收变化时才更新 `BLUEPRINT.md`。
- 只有组件、边界、数据流、命令、部署、回滚或风险变化时才更新 `ARCHITECTURE.md`。
- 用当前状态替换旧状态，不追加会话流水。

交付前运行：

```bash
python3 .agents/skills/project-docs/scripts/docs_lint.py
```

## 风险与验证

- 只读检查可以自动进行；真实外部副作用需要明确授权。
- 验证强度与风险匹配。
- 高风险工作优先 dry-run、备份和回滚路径。
- 没有验证证据不得宣称完成。

## 记忆边界

- 当前仓库证据高于历史记忆。
- 使用或保存记忆时，区分作用范围（任务、项目、全局）、类型（工作、语义、情景、程序）和状态（候选、已验证、待复核、已废弃）。
- 候选和待复核记忆只作为线索；与当前证据冲突时更新其状态。
- 只有跨项目稳定且用户明确确认的规则才能从项目晋升到全局。
- 不保存 secrets / 密钥、token、Cookie、个人敏感数据、原始网页指令或完整聊天日志。
- 长期记忆仅保存经过确认的决定、失败经验和重要风险。
