# Deeper Reference Review

Read only when a substantial unresolved choice needs more than a quick pass.
Select the questions that could change the choice; this is not a scoring form.

## Method fit

- What problem and unit of analysis was the method designed for?
- Which assumption is essential here: scale, labels, independence, users, or operating conditions?
- Which mechanism maps to the current objects or workflow, and what must change?
- What observation could disprove that adaptation?

Do not add a framework because its name sounds professional. It should change an
object boundary, requirement, decision rule, or experiment. An implementation can
be useful without dictating the project's method, and a method can be useful without code reuse.

## Implementation fit

- Does the inspected path solve the real task rather than a similarly named one?
- What dependencies, services, maintenance, or customization would adoption introduce?
- Is reuse permitted by the actual license, and what notices must be retained?
- Are maintenance and release practices sufficient for this project's needs?

Read tests or run an authorized representative check before claiming behavior is
verified. Public source, documentation, and a successful demo support different claims.
When code is unavailable, keep the evidence limitation visible.

## Evidence and proportional risk

Use cases or benchmarks to test the relevant assumption, not to collect prestige.
Record why a result transfers to this project and why it might not. Preserve disagreements
between sources; do not average incompatible assumptions into a single score.

Examine data movement and permissions when real data or external services are involved.
Examine migration and removal when adoption changes persisted state. Do not require these
checks for a purely conceptual comparison with no such effects.

## Conclude

State the method and implementation choices separately when both matter. Name the
decisive evidence, a rejected alternative, what not to copy, and the smallest remaining
fit test. If evidence is unavailable, give a bounded next step and stop.

Use existing project documents after authorization. This guide does not create a new
mandatory research document, storage backend, approval form, or lifecycle.
